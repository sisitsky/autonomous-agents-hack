    How the simulation works

    Two layers. The outer layer draws the uncertain parameters (error rate, claim propensity, claim size, systemic risk…) 2,000 times. For each draw the inner layer simulates 200 policy years of luck: a Poisson number of claims per peril, each with a lognormal-plus-Pareto size, then the deductible, per-claim limit, and aggregate limit, plus a possible systemic event at the model provider.

    The lines are years picked evenly across parameter draws, so they show both kinds of uncertainty: what we don't know about the risk, and luck. Colors run from blue (a cheap year) through gray to red (several times the expected loss). Flat stretches are months with no claims; each jump is one claim paid.

    The cloud is built from 4,000 simulated years: the darker band holds the middle half, the lighter band 90%. The density on the right is the whole simulation's annual-loss distribution.

    Convergence shows why 400,000 years: the running estimate of expected loss, with its ±2 standard-error band, narrows as years are added (simulated years shown in random order).

    Claim amounts and annual totals are the engine's own, so each line ends exactly at that year's simulated loss. Claim dates are spread uniformly over the year for illustration (the engine prices annual totals). Same seed, same picture.

      Dirichlet / Jewell credibility
      Every test case ends in a pass or exactly one failure type. How much to trust this system's own results versus the portfolio, for each type.
      Probability cloud: portfolio prior → this system's tests → posterior that is priced (shaded: 90% interval)
      Credibility Z rises with the number of cases tested
      Each system's rate is pulled toward the portfolio mean
      How credibility works here

      Jewell (1974): for the Dirichlet–multinomial the credibility estimate is exactly the Bayesian posterior mean, with one Z for every failure type. μ and A are re-estimated on every underwriting run from every other system tested on the same suite, so each new result updates the collective. The seed portfolio is fictional. Runs from this web page are not saved to the portfolio (read-only deployment); runs from the CLI are.

        Loop 2: the model learns from the world

        Every hour a monitor agent scans public sources for AI incidents, court decisions, enforcement actions, regulation and security signals. A calibration agent turns relevant evidence into a Bayesian update of a pricing parameter; a validation agent re-prices the benchmark book and checks the guardrails; the change lands as a GitHub pull request. Merging it is the human decision.
